## Why

Индекс v19 доказанно извлекает из обычных форм только форменный
`0-27/ПриОткрытии`. Для остальных событий и элементных обработчиков роль
`handlers` у всех 3 740 обычных форм остаётся `unsupported`, хотя исходные
JSON и модули содержат множество реальных привязок.

## What Changes

- Построить детерминированный инвентарь всех кандидатных привязок обработчиков
  обычных форм с группировкой по версии, позиционному пути, событию и области.
- Получить для каждого добавляемого класса минимальную контролируемую дельту
  конфигурации и, где требуется, журнал фактического вызова в 1С.
- Закрыть доказательствами все структурные классы форменных и элементных
  обработчиков, присутствующие в зафиксированном снимке 802, без
  эвристического распознавания неизвестных структур.
- Индексировать доказанные привязки через существующий `form_elements` и
  возвращать их через `parse_form()`.
- Довести роль `handlers` всех читаемых обычных форм зафиксированного снимка
  до `complete` либо `empty`; любой необъяснённый класс считать блокером
  реализации, который необходимо явно разрешить до изменения декодера.
- Не включать команды обычных форм: для них будет отдельный change и отдельная
  контролируемая дельта.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `v8unpack-form-json`: расширяется доказанное покрытие форменных и элементных
  обработчиков обычных JSON-форм.
- `v8unpack-form-helper-fallback`: `parse_form()` возвращает дополнительные
  доказанные привязки и точные состояния покрытия обработчиков.

## Impact

Изменятся закрытый реестр и оракул форм, `v8unpack_forms.py`, манифесты,
`parse_form()`, тесты и документация. Формат таблиц SQLite и новые зависимости
не требуются. Реализация потребует одношагового пробника 1С внутри `xpra`,
контролируемых исходного и изменённого CF и полной пересборки
`tn_bp20_custom_mcp`.
