## Why

Метаданные выгрузок Конфигуратора и EDT индексируются из XML/MDO, тогда как
`v8unpack` хранит эквивалентные сведения в JSON. Без отдельного адаптера
существующие запросы реквизитов, типов, ссылок и синонимов для такого источника
недоступны.

Реальный `v8unpack` JSON не является обычной объектной моделью: структура
реквизитов и типов находится в версионном позиционном массиве `header`.
Следовательно, поддержка должна быть ограничена проверенной версией формата и
не может сводиться к добавлению расширения `.json`.

## What Changes

- Добавить адаптер метаданных для маркера сериализации `v8unpack` `1.2.9` и
  `obj_version` `802`.
- На первом обязательном уровне поддержать конфигурацию и шесть уже
  индексируемых семейств объектов: справочники, документы, регистры сведений,
  накопления и бухгалтерии, планы видов характеристик.
- Для всех типов целей, которые уже знает `canonicalize_type_ref`, индексировать
  только имя и UUID, чтобы ссылки из шести структурных семейств разрешались без
  ложного статуса неполноты.
- Извлекать объекты, UUID, синонимы, реквизиты, табличные части, измерения,
  ресурсы, типы и ссылки по зафиксированному версионному контракту `header`.
- Записывать пользовательские сведения в существующие таблицы и контракты
  запросов. Добавить внутренние реестры идентичности объектов и сгенерированных
  `TypeId` для разрешения UUID; отдельный пользовательский API не создавать.
- Подключить один белый список ролей JSON к сбору метаданных, навигации и обоим
  путям инкрементального обновления.
- Хранить состояние полноты и ограниченный набор диагностик в `index_meta` и
  показывать их существующей командой сведений об индексе.
- Сохранить поведение XML/MDO для CF и EDT.

## Capabilities

### New Capabilities

- `v8unpack-metadata`: структурированная индексация подтверждённого подмножества
  JSON-метаданных `v8unpack` в существующую модель `rlm-tools-bsl`.

### Modified Capabilities

Отсутствуют.

## Impact

- Change зависит от `add-v8unpack-bsl-source-support`: формат источника и
  канонизация категорий должны быть доступны до выбора адаптера.
- Затрагиваются схема SQLite, сбор метаданных, навигация, полная и
  инкрементальная индексация, сведения об индексе, документация и тесты.
- `BUILDER_VERSION` повышается с `15` до `16`; старые индексы перестраиваются
  штатным механизмом несовпадения версии.
- Новые обязательные зависимости пакета не добавляются: рабочий разбор
  использует стандартную библиотеку Python.
- Поддержка ролей и прав, форм, команд, макетов, двоичных данных, XDTO и
  расширений конфигурации `v8unpack` остаётся вне этого change. Чтение имени и
  UUID роли как возможной цели ссылки не означает разбора её прав.
